# Ego and agent features

Generated by `python -m tools.extract_ego_agent_features check` (ego-agent-v1, 2026-10-29).
Extracts ego vehicle state and surrounding agent features at simulation iteration 0 for every benchmark candidate and the 68 mini scenarios.
Tables stay outside Git in `D:\nuplan\processed\features\ego_agent\`; this report and the code are committed.

## Time alignment

Iteration 0 is defined by the nuPlan devkit: the first `lidar_pc` at or after `anchor_timestamp_us - 3 s`, reading only data at or before that timestamp. This matches the devkit's simulation start and follows the `nuplan_scenario_mapping.yaml` offset `[-3.0, 15.0]` for all 14 challenge types.

## Features

### Ego vehicle state (rear axle frame)

| Column | Meaning | Frame | Unit |
|---|---|---|---|
| `ego_x` | Rear axle position x | Global map frame | m |
| `ego_y` | Rear axle position y | Global map frame | m |
| `ego_heading` | Rear axle heading | Global map frame | rad |
| `ego_speed` | Speed magnitude | - | m/s |
| `ego_acceleration` | Acceleration magnitude | - | m/s² |
| `ego_yaw_rate` | Angular velocity (yaw rate) | - | rad/s |

**Note:** Ego velocity components in `ego_pose` are stored in the ego frame. They are rotated by heading to compute the global-frame speed and acceleration. Position differences match rotated velocities to a median error of 0.19 m/s (vs 8.9 m/s if read as global), confirming the frame interpretation.

### Surrounding agents (vehicles, pedestrians, bicycles)

| Column | Meaning | Unit |
|---|---|---|
| `num_tracked_agents` | Total count of all tracked objects | count |
| `num_vehicles` | Count of vehicles only | count |
| `num_pedestrians` | Count of pedestrians only | count |
| `agents_within_50m` | Count within 50 m of ego center | count |
| `nearest_agent_distance_m` | Distance to nearest agent (center-to-center) | m |
| `nearest_agent_relative_speed_mps` | Closing speed with nearest agent | m/s |

**Distance computation:** Euclidean distance from ego center (rear axle + 1.461 m forward along heading, Pacifica parameter) to agent box center.

**Closing speed:** Rate of change of distance, computed as `-(dx·Δvx + dy·Δvy) / distance`, where Δv = agent velocity - ego velocity (both in global frame). Positive means approaching, negative means separating. Null when no agent is present.

**Agent categories:** Vehicles (`vehicle`), pedestrians (`pedestrian`), and bicycles (`bicycle` and `motorcyclist`). Barriers and generic objects are excluded.

## Validation

The extractor was verified against the devkit's per-scenario SQL query on all 68 mini scenarios. Maximum absolute difference: 1e-14 (floating-point precision).

**Checks:**

- PASS: one shard per log with candidates
- PASS: no failed logs
- PASS: one row per benchmark candidate
- PASS: 68 mini_68 rows matching the manifest
- PASS: scenario_id unique
- PASS: every scenario has a start frame and ego pose
- PASS: start frame within [anchor - 3 s, anchor - 3 s + 0.1 s)
- PASS: ego_pose matched within 0.1 s of the lidar frame
- PASS: physical ranges (speed < 45 m/s, |accel| < 20, |yaw rate| < 3)
- PASS: counts consistent (vehicles + pedestrians ≤ tracked; within-50m ≤ tracked)
- PASS: nearest distance ≤ 50 m whenever an agent is within 50 m
- PASS: nearest-agent values null only when no agent is present

**Unit tests:** 10 tests covering heading computation, start frame selection, ego features, agent counts/distance/closing, velocity frame interpretation, null handling, and vectorized vs. devkit comparison.

## Implementation notes

- Ego pose velocity is stored in the ego frame in the nuPlan DB; it is rotated to the global frame by the extractor.
- Agent box velocity is stored in the global frame; no rotation needed.
- The extractor uses vectorized Pandas operations per log for speed (40+ logs/s), verified against the devkit's row-by-row SQL query.
- The 6 logs that failed the initial build had a pandas ambiguity error (fixed by using `.merge` instead of `.join`).
